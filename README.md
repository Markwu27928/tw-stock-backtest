# 台股 20 日選股回測

每個交易日自動抓證交所資料、重跑回測，產生手機版報告頁，用來檢驗「每月選出的股票有沒有 6 成跑贏 0050」。

## 策略與規則

| 項目 | 規則 |
|---|---|
| 母體 | 上市普通股（排除 ETF、TDR）、股價 ≥ 10 元、20 日均成交金額 ≥ 2,000 萬、上市滿 60 個交易日 |
| 決策日 | 每月第一個 ≥ 11 日的交易日收盤後（月營收 10 日公告截止） |
| 進出場 | 決策日的下一個交易日收盤買進，持有到下個月同一時點賣出（約 20 個交易日） |
| 選股 | 每個策略選分數最高的 10 檔，等權重 |
| 成本 | 手續費 0.1425%×2（可設折數）＋證交稅 0.3% |
| 報酬 | 已還原除權息；基準為 0050（同樣還原） |

三個策略：

- **A 月營收年增率單因子**：上個月營收 YoY 最高的 10 檔
- **B 多因子綜合分數**：營收 YoY、YoY 加速、6 個月動能（跳過最近 1 個月）、投信 20 日買超、近 1 個月反轉、距 52 週高點，排名平均
- **C LightGBM**：13 個特徵，每月只用「已經結束」的歷史月份重新訓練（walk-forward，不會偷看未來）

報告指標：選股勝率（選中個股扣成本後跑贏 0050 的比例）、隨機選股基準、月勝率、年化報酬、最大回撤、t 值（> 2 代表勝率高於隨機，不太可能是運氣）。

## 資料來源

| 資料 | 來源 |
|---|---|
| 每日收盤行情 | 證交所 MI_INDEX |
| 三大法人買賣超 | 證交所 T86 |
| 除權息 | 證交所 TWT49U |
| 月營收 | 公開資訊觀測站彙總表；最新月份用證交所 OpenAPI 補；觀測站連不上時改用 FinMind（可選填 token） |

資料存在 `data/`，每天一個小檔，不會重複抓。

## 設定步驟（約 10 分鐘）

1. 在 GitHub 建一個新 repo（例如 `tw-stock-backtest`），把這個資料夾所有檔案上傳（包含 `.github` 資料夾）。
   建議設為 **Public**：Actions 分鐘數不限、GitHub Pages 免費；頁面已加 noindex，不會被搜尋引擎收錄。
2. **Settings → Actions → General → Workflow permissions** 選 **Read and write permissions** → Save。
3. **Settings → Pages**：Source 選 **Deploy from a branch**，Branch 選 `main`、資料夾選 `/docs` → Save。
4. **第一次回補歷史資料**：Actions → 每日回測 → Run workflow，`max_minutes` 填 **330**。
   2015 年至今約 2,500 個交易日，每天要抓 2 次，證交所需要間隔約 4 秒，總共約 6 小時，所以要手動跑 **2 次**（第一次跑完再按一次）。
   之後每天 17:20 自動更新，只抓當天資料，約 3 分鐘。
5. 手機打開 `https://<你的帳號>.github.io/tw-stock-backtest/`。

選填：

- **Settings → Secrets and variables → Actions → Secrets**：`FINMIND_TOKEN`（只有觀測站連不上時才會用到）
- 同頁 **Variables**：`FEE_DISCOUNT`，例如手續費 6 折填 `0.6`

## 回補期間的顯示

歷史資料還沒補完時，報告頁只顯示「連續完整區間」內的回測，「本月持股」會等資料補完才出現。資料狀態區塊有進度條。

## 測試

```bash
pip install -r requirements.txt
python -m pytest -q tests
```

測試用合成市場跑完整流程，包含：

- 證交所、觀測站各種回應格式的解析（新舊欄位名稱、假日、沒成交）
- 抓資料中斷後能接續、最近資料優先
- 除權息還原
- **前視偏差檢查**：把 2017-12 之後的資料全部打亂，之前的回測結果必須完全不變
- **雜訊對照**：在沒有任何訊號的市場，三個策略都不能做出高於隨機的勝率
- 植入訊號時能被找出來

GitHub Actions 每天會先跑測試，沒通過就不更新報告。

## 已知限制

- 目前只有上市股票，上櫃在 v2 加入
- 減資、分割沒有還原，用每日 ±11% 截斷避免假報酬
- 以收盤價成交，未計入大量買賣的價格衝擊
- 僅供研究，不構成投資建議
